# شواهد بلوغ فناوری (TRL) — inno-medical-records-nlp

**ادعا: TRL 4** (اعتبارسنجی اجزا در محیط آزمایشگاهی). **TRL 5 ادعا نمی‌شود.**

## شواهد
| سطح | شاهد |
|---|---|
| TRL 2 | مفهوم و معیار موفقیت در README و جدول زیر تعریف شده است. |
| TRL 3 | اثبات مفهوم روی داده‌ی مصنوعی: `src/inno_medical_records_nlp/core.py`، تولیدکننده‌ی داده‌ی قطعی (`generate`). |
| TRL 4 | اجزا (داده → مدل/قواعد → هشدار/خروجی) با تست واحد و معیارهای پذیرش خودکار روی ۳ seed مستقل؛ CI در `.github/workflows/ci.yml`. |

## معیارهای پذیرش TRL 4
| معیار | شرط |
|---|---|
| entity extraction F1 (type + normalised text) | >= 0.9 |
| negation status accuracy on matched entities | >= 0.9 |
| ICD-10 suggestion accuracy on true conditions | >= 0.9 |

نتایج اجرا: [VALIDATION.md](VALIDATION.md) (بازتولید: `python -m inno_medical_records_nlp validate`).

## آنچه پیاده‌سازی شده
نرمال‌سازی فارسی (ی/ک عربی، نیم‌فاصله، ارقام)، استخراج موجودیت با واژگان + تطبیق تقریبی (یک ویرایش)، نفی در محدوده‌ی جمله، پیشنهاد ICD-10 با پرچم بازبینی انسانی.

## فرض‌های داده‌ی مصنوعی و محدودیت‌ها
یادداشت‌ها از قالب‌های ساده با واژگان همان سیستم ساخته می‌شوند؛ بنابراین امتیاز بالا خوش‌بینانه است و روی متن آزاد واقعی افت خواهد کرد. واژگان فقط ۲۲ مدخل نمونه است.

عملکرد روی داده‌ی مصنوعی تضمین‌کننده‌ی عملکرد روی داده‌ی واقعی نیست. خروجی‌ها پشتیبان تصمیم‌اند و جایگزین قضاوت بالینی/کارشناسی نیستند.

## لازمه‌های رسیدن به TRL 5
نمونه‌ی بی‌نام‌شده‌ی پرونده‌های واقعی با برچسب کدگذار، واژگان کامل ICD-10 فارسی، مدل یادگیری برای املای آزاد و اختصارات.
